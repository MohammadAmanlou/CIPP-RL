# Stage 4 Audit and Corrections

## Critical correctness fixes

1. **Professor repeat-penalty offset was ignored by the shared evaluator.**
   The environment and Gurobi model used `repeat_factor`, but
   `deterministic_objective` still hard-coded `1 - gamma * count`.  This made
   real-instance RL rewards, final evaluation and Gurobi objectives inconsistent.
   The evaluator now always calls `instance.repeat_factor(count)`.

2. **The supplied code and the revised paper use different smallest-instance labels.**
   In the supplied Python script, `Cities=16` creates indices `0..15`; index 0
   is `Rest`, so there are **15 real visit locations**.  The revised paper calls
   its smallest class `14S`.  The project no longer silently labels 15 actions
   as `14S`:
   - `--instance-mode supplied-code` -> `D/R_15S_30P_CODE`
   - `--instance-mode paper-14` -> `D/R_14S_30P_PAPER_SHAPE`

3. **Legacy rolling-window indexing was ambiguous.**
   The supplied script uses `alpha=6` with an inclusive sum, producing an
   effective seven-day window.  The corrected canonical model uses complete
   seven-day windows, consistent across evaluator, mask, RL and Gurobi.

4. **Action masking was correct but too slow for large DQN training.**
   The previous mask re-evaluated every full prefix for every action.  The new
   exact mask checks only active rolling windows and reduced the 1,000-episode
   validation runtime from minutes to a few seconds in this environment.

5. **The random comparison was statistically unclear.**
   The benchmark now distinguishes:
   - the distribution over 30 Random Feasible runs;
   - Random Best-of-30 as one search procedure with 30 rollout attempts.

6. **Gap columns mixed two different meanings.**
   The output now separates:
   - best/mean gap to the Gurobi reference;
   - Gurobi's own MIP gap to its bound;
   - reference type (`proven optimum` or non-certified incumbent).

## Training and evaluation improvements

- One frozen DQN checkpoint is evaluated in two modes:
  `DQN-Greedy` and `DQN-Backtracking-K`.
- Backtracking performs no gradient update and never modifies model weights.
- Backtracking priorities combine the exact scaled prefix return with the DQN
  estimate, so alternatives from different decision depths are compared on the
  same root-to-go scale.
- Five model seeds see the same training and validation instance seeds.
- Training instances are generated by blending D/R empirical reward profiles,
  applying scale/jitter, and randomly permuting locations.
- Validation selects `best.pt`; `last.pt` is saved separately.
- Three learning-curve figures are generated for every seed.
- Checkpoints include model/optimizer/normalizer/configuration and distribution
  metadata.
- Processed CSV copies of the XLS reward/ID data are included, allowing the
  benchmark to run without `xlrd`; raw XLS files remain for provenance.
